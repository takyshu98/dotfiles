# エージェント駆動・低メンテナンス設計を採用する

対応ソフトウェアが増えるたびにスキルの実装(検出パターン、設定ファイルのパーサー、Default Keybindの調達コード)を手で追加していくと保守コストが際限なく膨らむ。そこで、ソフトウェア固有の知識が必要になる3つの局面すべてで、専用コードではなくエージェント(LLM)の読解力に委ねる方針を採る。

- **Software Catalogの成長**: 未知の設定ファイルを見つけたら専用パターンを書き足すのではなく、エージェントに推測させ、ユーザー確認後にカタログへ自己追記する([[Software Catalog]])。
- **Default Keybindの取得**: ソフトウェア自身のCLI内省コマンドを優先し、無ければ公式ドキュメントをエージェントが読んで抽出する([[Default Keybind]])。
- **設定ファイルの解析**: TOML/JSON/Lua/独自DSLなど形式ごとに専用パーサーを書かず、エージェントに生テキストを読解させてKeybind定義を抽出する。

トレードオフとして、フォーマットが機械的にパース可能な場合(TOML/JSONなど)でも決定的なパーサーより低速・低確実性になりうるが、Luaのような汎用言語で書かれた設定ファイルはそもそも静的パースが非現実的であり、全ソフトウェアで抽出経路を統一できる利点がこれを上回ると判断した。
